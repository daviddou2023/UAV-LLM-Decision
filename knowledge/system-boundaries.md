# 两设备职责边界

最后更新：2026-07-14

本仓库当前主要承载第二个设备（设备二）的仿真、决策、规划和决策输出。联调系统由两个设备组成：

## 设备一：郭老师设备/地面统筹设备

设备一负责地面统筹和真实执行闭环。

- 接收雷达原始数据。
- 对雷达数据进行清理、过滤和态势汇总。
- 将当前战场态势发送给设备二。
- 接收设备二回发的决策帧。
- 根据决策帧实际操控无人机运动。
- 在指挥大屏显示态势、任务、路径和执行状态。

在本仓库中的对应入口主要是输入适配和历史显示/飞控兼容模块：

- `perception/radar_feed.py`
- `perception/udp_gateway.py`
- Redis/Fusion 数据源
- `integrations/middle_layer.py` 等历史显示适配

## 设备二：我方决策外挂

设备二是本仓库当前主要实现的系统。它根据设备一提供的当前战场态势进行决策，核心决策内容包括：

1. 任务分配：决定己方哪架无人机锁定敌方哪架无人机，以及采用哪种拦截方式。
2. 路径规划：任务分配完成后，决定己方无人机如何飞到目标点或编队槽位。
3. 动作建议：为每架 UAV 输出解锁、起飞、切模式、上传短航点或等待等动作建议。
4. 态势总结：生成一句话态势警报/提示。

设备二在本仓库中的主要模块：

- `simulation/main.py`：设备二仿真环境和主流程编排。
- `decision/cooperation.py`：撞击模式任务分配。
- `decision/deconfliction.py`：局部避碰和路径点规划。
- `station/contracts.py`：把任务分配和路径规划结果转换为完整 `PlanFrame`。
- `station/query.py`：从 `PlanFrame` 裁剪 `decision_output_frame` 和其他查询视图。
- `station/exporter.py`：按设备一输入帧触发回发决策结果。
- `station/feedback.py`：处理设备一执行回执。
- `decision/llm_kit.py`：态势一句话警报和战术副官文本。
- `decision/llm_task_constraints.py`：把 LLM/指挥员自然语言任务口令解析为设备二内部约束字典。

## 当前重构边界

- 本仓库优先把设备二内部流程接口化：任务分配、路径规划、`PlanFrame` 构造、精简决策帧裁剪、发布、反馈处理。
- 设备一输入接口只做适配和归一化，不把设备二决策写入输入层。
- 设备一飞控执行和大屏显示不在设备二核心算法中实现。
- 新增外部查询/服务接口时，优先复用 `PlanFrameBuilder` 和 `station/query.py`，不要绕开现有状态重新造一套协议。
- `station/` 是历史目录名，当前语义是“决策输出模块”；不为改名做大范围目录迁移。
