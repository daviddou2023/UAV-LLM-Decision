# 04 端到端联调流程

最后更新：2026-07-14

## 联调目标

验证数据能从设备一进入设备二，并由设备二回发一帧决策结果给设备一：

```text
设备一清理后的当前战场态势
  -> perception 输入处理
  -> simulation/main.py 决策主循环
  -> decision 任务分配与路径规划
  -> station PlanFrame / decision_output_frame
  -> 设备一操控无人机并在指挥大屏显示
  -> station/feedback.py 回执闭环
```

关键触发规则：**每收到一次设备一输入帧，设备二完成一次决策后回发一帧决策帧。**

## 推荐联调顺序

### 1. 输入层自检

```powershell
python -m perception.ingest
```

确认点：

| 观察项 | 期望 |
| --- | --- |
| `RadarIngestService.poll()` | 能包装任意 `feed.poll()` 字典输出 |
| `RadarTrackFrame.to_snapshot()` | 仍包含 `enemies/friendlies/meta/events` |
| `meta.frame` / `meta.seq` | 至少有一个能随设备一输入帧变化 |

### 2. 态势接入观察

运行主程序后看日志：

| 日志标签 | 含义 | 典型问题 |
| --- | --- | --- |
| `[DATA]` | 输入源连接、诊断、实时/兜底切换 | Redis/UDP 无数据、字段不全、连接失败 |
| `[RADAR]` | 新建敌方航迹 | external_id 抖动会导致重复新建 |
| `[REACQ]` | 丢失目标重获 | lost/stale 状态恢复 |

验收：`env.last_live_packet_meta` 能记录设备一输入帧元数据，`env.enemies` 和 `env.interceptors` 持续刷新。

### 3. 决策层自检

```powershell
python -m py_compile decision/pipeline.py
python -m decision.pipeline
```

确认点：

| 观察项 | 期望 |
| --- | --- |
| `DecisionPipelineService.tick(dt)` | 能调用 `env.step(dt)` 并返回本帧日志 |
| `DecisionSnapshot.assignments` | 能从 `env.interceptors` 读到当前绑定 |
| `DecisionSnapshot.alert` | 能生成一句话态势摘要 |

运行主程序时看 `[AI情报]`、`[LLM]`、`[ASGN]`、`[BARRIER]`、`[NET]`、`[PATH]` 等日志。

### 4. 输出层自检

```powershell
python -m py_compile station/output.py
python -m station.output
python -m station.query
python -m station.plan_bridge
```

确认点：

| 观察项 | 期望 |
| --- | --- |
| `StationOutputService.from_env(env)` | 生成完整 `plan_frame` 和 `decision_output_frame` |
| `decision_output_frame_from_plan_frame(frame)` | 能裁剪出 `commands[]` |
| `station_flight_commands_from_frame(frame)` | 能裁剪出飞控指令视图 |
| `build_station_transfer_packet(frame)` | 历史旁路转接仍能通过绑定校验 |

### 5. 设备二回发设备一 Socket 联调

在 `core/common.py` 中开启：

```python
PLAN_EXPORT = {
    "enabled": True,
    "transport": "tcp_json_lines",
    "publish_policy": "input_frame",
    "output_frame_type": "decision_output_frame",
    "socket_host": "设备一接收IP",
    "socket_port": 7001,
    ...
}
```

运行后看日志：

| 日志标签 | 含义 | 处理建议 |
| --- | --- | --- |
| `[PLAN] 设备一决策Socket已连接` | 主决策帧通道可用 | 继续看设备一是否收到 JSON Lines |
| `[PLAN] 设备一决策Socket暂未发送成功` | TCP 未连接或发送失败 | 检查地址、端口、防火墙、设备一服务端 |
| `[PLAN] 设备一执行失败` | 设备一回传 failed/aborted | 检查 UAV 编号映射和执行侧故障原因 |

## 最小验收清单

| 阶段 | 必须通过 |
| --- | --- |
| 输入 | 设备一态势帧能被 `poll()` 读到，`meta.diag` 无持续错误 |
| 环境 | `env.enemies` 和 `env.interceptors` 坐标持续刷新 |
| 分配 | `[ASGN]`/`[BARRIER]`/`[NET]` 日志符合当前模式 |
| 路径 | 每个执行任务 UAV 有 `path_plan` 或明确 `failure_reason` |
| 完整帧 | 设备二能生成 `PlanFrame`，且含 `situation_alert` |
| 精简帧 | `decision_output_frame.commands[]` 包含任务绑定、动作、航点和下一指令点 |
| 触发 | 同一个设备一输入帧只回发一次；新输入帧到来后回发新决策帧 |
| 回执 | 设备一 ACK/失败/状态能被处理并写入日志 |

## 常见问题定位

| 现象 | 优先检查 |
| --- | --- |
| 没有回发决策帧 | `PLAN_EXPORT["enabled"]` 是否为 `True`；`publish_policy` 是否为 `input_frame`；`meta.frame/seq/timestamp` 是否至少有一个变化 |
| 重复回发同一输入帧 | 设备一输入 `meta` 是否缺少稳定帧号；检查 `last_live_packet_meta` |
| 有任务但没航点 | `_route_points_for()`、`path_plan`、`_route_status()` |
| 设备一不知道谁打谁 | `commands[].target_id`、`assignment_id`、`assignment_epoch` 是否为空 |
| 设备一飞错 UAV | `PLAN_EXPORT["uav_id_map"]` 与现场 `uav_id/drone_id` 是否一致 |
| 频繁切任务 | `assignment_epoch` 是否因 signature 抖动频繁递增 |
| 输入目标重复出现 | `LocalEnemyAssociator.associate()` 的稳定 ID 匹配是否生效 |
