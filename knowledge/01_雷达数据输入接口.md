# 01 战场态势输入接口

最后更新：2026-07-14

## 目标

把设备一提供的“当前战场态势”统一接入设备二，形成设备二内部可直接使用的敌我双方状态。

设备一已经完成雷达原始数据接收、清理和过滤；设备二输入层只做必要的读取、解析、坐标归一化、稳定 ID 关联和同步到环境状态。输入层不做任务分配，不生成飞控动作。

## 代码落点

| 文件 | 职责 | 主要函数 |
| --- | --- | --- |
| `perception/ingest.py` | 态势输入薄接口 | `RadarIngestService.poll()` |
| `perception/radar_feed.py` | Redis/融合航迹读取、清洗、平滑、格式归一化 | `TeacherDataFeed.poll()`、`_collect_live_sources()`、`_normalize_tracks()`、`FusionTrackFeed.poll()` |
| `perception/udp_gateway.py` | UDP 航迹输入 | `TeacherUDPFeed.poll()` |
| `perception/enemy_association.py` | 敌方目标稳定 ID 关联 | `LocalEnemyAssociator.associate()` |
| `simulation/main.py` | 把归一化航迹同步进设备二决策环境 | `_pump_live_data()`、`_sync_teacher_data()`、`_upsert_live_enemies()`、`_sync_live_friendlies()` |

## 外部调用接口

```python
from perception import RadarIngestService

service = RadarIngestService(feed)  # feed 可为 TeacherDataFeed / FusionTrackFeed / TeacherUDPFeed
frame = service.poll(sim_time=env.time)
```

`RadarTrackFrame` 保留现有字段：

| 字段 | 含义 | 下游使用 |
| --- | --- | --- |
| `enemies` | 敌方航迹列表，已带本地坐标、速度、航向、质量等 | `InterceptionEnvironment._upsert_live_enemies()` |
| `friendlies` | 己方航迹列表，已映射到本地坐标 | `InterceptionEnvironment._sync_live_friendlies()` |
| `meta` | 连接状态、帧号、时间戳、诊断信息 | 日志、`last_live_packet_meta`、决策输出触发和帧追踪 |
| `events` | 输入层告警或关联事件 | UI/日志排查 |

## 数据调用回路

```text
simulation/main.py::InterceptionEnvironment.step(dt)
  -> _pump_live_data()
    -> _sync_teacher_data()
      -> self.feed.poll(self.time)
        -> TeacherDataFeed.poll() / FusionTrackFeed.poll() / TeacherUDPFeed.poll()
          -> _collect_live_sources() 读取设备一态势输入
          -> _parse_value() 把字符串值解析为 Python 数值/结构
          -> _normalize_tracks() 分敌我、坐标投影、状态归一化
          -> LocalEnemyAssociator.associate() 为敌方目标分配稳定 external_id
      -> _upsert_live_enemies(enemies) 写入 env.enemies
      -> _sync_live_friendlies(friendlies) 写入 env.interceptors
```

## 输入帧元数据

`InterceptionEnvironment._sync_teacher_data()` 会把输入 `meta` 保存到：

```python
env.last_live_packet_meta = {
    "device_id": meta.get("device_id"),
    "seq": meta.get("seq"),
    "timestamp": meta.get("timestamp"),
    "frame": meta.get("frame"),
}
```

该字段有两个用途：

1. `station/contracts.py::_radar_frame_id()` 将其写入 `PlanFrame.radar_frame_id`。
2. `station/exporter.py::PlannerExporter` 在 `publish_policy="input_frame"` 时用它去重，优先使用 `frame`，其次 `seq`，最后 `timestamp`，保证同一设备一输入帧只回发一次决策帧。

## 边界约束

- 输入层不决定哪架己方无人机打哪个目标。
- 输入层不生成飞控命令，动作建议只能由 `station/contracts.py` 和 `station/query.py` 基于决策结果生成。
- 新增设备一数据源时，只要实现 `poll(sim_time)` 返回 `enemies/friendlies/meta/events`，即可接入 `RadarIngestService`。
