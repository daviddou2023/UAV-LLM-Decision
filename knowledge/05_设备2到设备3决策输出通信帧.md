# 05 设备二回发设备一完整决策输出通信帧

最后更新：2026-07-14

> 文件名沿用旧“设备2到设备3”命名，避免引用断裂；当前真实语义是“设备二回发设备一”。

## 1. 文档目的

本文档面向设备一对接，说明设备二完整 `PlanFrame` 的字段。设备二需要把四类结果回发设备一：

1. 一句话态势总结。
2. 任务分配：哪架己方无人机执行哪个目标、任务角色是什么。
3. 路径规划：该无人机下一步怎么飞、航点和速度是多少。
4. 单机动作建议：解锁、起飞、切模式、上传短航点或等待。

当前代码以 `PlanFrame` 作为完整决策帧，由 `station/contracts.py::PlanFrameBuilder.build()` 生成；主链路默认会再裁剪成 `decision_output_frame` 发送，完整帧仍作为调试、旁路和后续扩展的稳定来源。

## 2. 通信方式

| 项目 | 取值 |
| --- | --- |
| 传输协议 | TCP Socket |
| 消息编码 | UTF-8 JSON |
| 分帧方式 | JSON Lines，一行一帧，以 `\n` 结尾 |
| 发送方向 | 设备二 -> 设备一 |
| 完整帧消息类型 | `msg_type = "plan_frame"` |
| 默认主链路消息类型 | `msg_type = "decision_output_frame"` |
| 默认触发策略 | `PLAN_EXPORT["publish_policy"] = "input_frame"` |
| 生成位置 | `station/contracts.py::PlanFrameBuilder.build()` |

## 3. 完整帧结构

```json
{
  "msg_type": "plan_frame",
  "schema_version": "planframe.v1",
  "producer": {
    "device": "device2",
    "module": "device2_planner"
  },
  "frame_id": "plan_frame_00000001",
  "plan_seq": 1,
  "radar_frame_id": 1001,
  "timestamp_ms": 1783766400000,
  "valid_duration_ms": 1500,
  "valid_until_ms": 1783766401500,
  "situation_alert": "当前发现2个活动目标，6架我方无人机可用，3个任务绑定。",
  "coordinate_frame": {},
  "transport": {},
  "execution_policy": {},
  "assignment_plan": {
    "status": "planned",
    "assignments": []
  },
  "route_plan": {
    "status": "planned",
    "routes": []
  },
  "groups": []
}
```

## 4. 顶层字段

| 字段名称 | 类型 | 取值/说明 |
| --- | --- | --- |
| `msg_type` | string | 固定为 `plan_frame` |
| `schema_version` | string | 当前默认 `planframe.v1` |
| `producer.device` | string | 固定为 `device2` |
| `producer.module` | string | 默认 `device2_planner` |
| `frame_id` | string | 规划帧编号，格式如 `plan_frame_00000001` |
| `plan_seq` | int | 设备二决策输出序号，每生成一帧递增 |
| `radar_frame_id` | int/null | 本帧基于的设备一输入帧号 |
| `timestamp_ms` | int64 | 设备二生成本帧的 Unix 毫秒时间戳 |
| `valid_duration_ms` | int | 本帧有效时长，默认 `1500` |
| `valid_until_ms` | int64 | 本帧有效截止时间 |
| `situation_alert` | string | 一句话态势总结 |
| `assignment_plan` | object | 任务分配计划 |
| `route_plan` | object | 路径规划与动作计划 |
| `groups` | array | 多机协同编组信息 |

## 5. 一句话态势总结

`PlanFrame.situation_alert` 由 `station/contracts.py::_situation_alert()` 生成，统计口径如下：

| 变量 | 来源 | 说明 |
| --- | --- | --- |
| 活动目标数量 | `env.enemies` | 目标状态为 `APPROACHING` 或 `MANEUVERING`，且未 `lost` |
| 可用无人机数量 | `env.interceptors` | 未 `DESTROYED`、未 `LANDED`、未被执行侧失败回执临时屏蔽 |
| 任务绑定数量 | `env.interceptors[*].target_id` | `target_id` 非空的 UAV 数量 |

## 6. 任务分配计划

`assignment_plan.assignments[]` 每架被导出的 UAV 一条：

| 字段名称 | 类型 | 取值/说明 |
| --- | --- | --- |
| `assignment_id` | string | 单机任务分配唯一 ID，如 `asg_uav_01_e0001` |
| `assignment_epoch` | int | 同一 UAV 任务代数；目标、任务或角色变化时递增 |
| `group_id` | string | 协同组 ID |
| `uav_id` | string | 设备一可读 UAV 字符串 ID |
| `drone_id` | int | 设备一/飞控使用的数字无人机 ID |
| `uav_internal_id` | int | 设备二内部 UAV ID |
| `target_id` | string/null | 目标外部 ID |
| `target_internal_id` | int/null | 设备二内部目标 ID |
| `mission_type` | string | `intercept`、`barrier_net`、`net_capture`、`return_home`、`retask_pending`、`uav_unavailable` |
| `role` | string | `primary`、`backup`、`reserve` |
| `formation_role` | string/null | 编队槽位 |
| `state` | string | `planned`、`en_route`、`completed`、`failed` 等 |
| `target_lock_state` | string | `new_lock`、`locked`、`released`、`retask_pending`、`none` |
| `target_snapshot` | object/null | 目标状态快照 |

## 7. 路径规划计划

`route_plan.routes[]` 每架被导出的 UAV 一条：

| 字段名称 | 类型 | 取值/说明 |
| --- | --- | --- |
| `route_id` | string | 单机路径 ID |
| `assignment_id` | string | 必须与对应 assignment 的 `assignment_id` 一致 |
| `uav_id/drone_id` | string/int | 必须与对应 assignment 一致 |
| `target_id` | string/null | 当前路径服务的目标 ID |
| `status` | string | `planned`、`pending`、`infeasible`、`failed` |
| `failure_reason` | string | 不可行、等待或失败原因 |
| `control_intent` | object | 设备二给设备一的动作意图 |
| `path_reason` | string | 设备二路径原因说明 |
| `speed_mps` | float | 建议速度 |
| `waypoints` | array | 短路径点列表 |
| `next_command_point` | object/null | 下一指令点，通常等于 `waypoints[0]` |

## 8. 控制意图

`route_plan.routes[].control_intent.low_level_actions[]` 是设备一执行侧最关心的动作列表：

| `command` | 中文含义 | 建议动作 |
| --- | --- | --- |
| `arm` | 解锁 | 如未解锁则执行 |
| `takeoff` | 起飞 | 如未在空中则起飞到 `alt_m` |
| `set_mode` | 切模式 | 按 `mode` 切到指定模式 |
| `upload_short_waypoints` | 上传/覆盖短航点 | 用最新短航点覆盖旧路径 |
| `hold` | 等待/保持 | 不上传新路径，等待下一帧 |

## 9. 设备一最小消费建议

设备一若只需要操控和大屏显示，优先消费 `decision_output_frame`；若需要调试完整状态，再查看 `PlanFrame`。两者由同一份 `PlanFrame` 生成，`assignment_id + uav_id + drone_id` 必须一致。
