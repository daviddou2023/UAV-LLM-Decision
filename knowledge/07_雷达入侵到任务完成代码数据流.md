# 雷达入侵到任务完成代码数据流

最后更新：2026-07-14

本文按工程真实执行顺序说明：当设备一发现敌方无人机入侵，并把当前战场态势送入设备二后，设备二代码中哪些文件、哪些函数依次处理数据，直到任务完成或等待设备一回执闭环。

> 说明：仓库内 `station/`、`Device3FeedbackHandler`、`device3_*` 等命名仍保留历史地面站/设备三叫法。当前两设备结构下，可理解为“设备二回发设备一”和“设备一执行侧回执”。

## 0. 总流程

```text
设备一雷达/清洗态势
  -> perception feed.poll()
  -> simulation/main.py::_sync_teacher_data()
  -> env.enemies / env.interceptors
  -> simulation/main.py::step()
  -> decision/cooperation.py 或 simulation/main.py 编队分配
  -> decision/deconfliction.py 局部避碰与航点规划
  -> station/contracts.py 构建 PlanFrame
  -> station/query.py 裁剪 decision_output_frame
  -> station/exporter.py / socket_client.py 回发设备一
  -> station/feedback.py 处理设备一回执，必要时重分配
```

主循环是 `simulation/main.py::run_demo()`，核心业务 tick 是 `InterceptionEnvironment.step(dt)`。读代码时可以先抓住这两个入口。

## 1. 程序启动与主循环

### `simulation/main.py::run_demo(...)`

职责：实例化环境、输入源、渲染器和决策帧发布器，然后进入循环。

关键操作：

1. 创建 `InterceptionEnvironment(...)`，把 `source`、Redis/UDP 参数、拦截模式、坐标映射等配置传入环境。
2. 如果 `core.common.PLAN_EXPORT["enabled"]` 打开，创建 `station/exporter.py::PlannerExporter`。
3. 每个固定时间步调用 `env.step(CFG.DT)` 推进设备二决策状态。
4. 每轮循环末尾调用 `plan_exporter.maybe_publish(env)`，把本轮生成的任务绑定、动作和航点回发设备一。
5. 如果仿真还未按回车开始，但 `source in ("udp", "redis", "auto", "fusion")`，仍会调用 `env._pump_live_data()` 后台抽取真实态势，避免输入积压。

对应主链路：

```text
run_demo()
  -> env.step(CFG.DT)
  -> plan_exporter.maybe_publish(env)
```

## 2. 设备一态势输入进入设备二

### `simulation/main.py::InterceptionEnvironment.step(dt)`

职责：设备二一次决策 tick 的总入口。

第一步就是：

```text
step(dt)
  -> self._pump_live_data()
  -> self._sync_teacher_data()
```

### `simulation/main.py::_pump_live_data()`

职责：选择真实输入还是本地演示输入。

执行逻辑：

1. 调用 `_sync_teacher_data()` 尝试读取设备一输入帧。
2. 如果不是演示模式，调用 `_age_live_tracks()` 标记雷达航迹延迟/丢失。
3. 如果是演示模式，调用 `_spawn_demo_waves()` 生成本地回放敌机。

### `simulation/main.py::_sync_teacher_data()`

职责：把输入层快照同步进设备二环境状态。

执行逻辑：

1. 调用 `self.feed.poll(self.time)` 拉取一帧态势。
2. 从返回快照中取出 `enemies`、`friendlies`、`meta`、`events`。
3. 写入 `self.last_live_packet_meta`，保存 `device_id`、`seq`、`timestamp`、`frame`。
4. 如果收到敌机或己方机：
   - 设置 `self.has_live_data = True`。
   - `source == "auto"` 时关闭本地回放，切换到设备一实时数据。
   - 调用 `_upsert_live_enemies(enemies)`。
   - 调用 `_sync_live_friendlies(friendlies)`。
5. 如果 `auto` 模式 2 秒内没有真实数据，才启用本地演示兜底。

`last_live_packet_meta` 后续会被 `station/exporter.py::_input_frame_key()` 使用，用来实现“每收到一次设备一态势帧，就回发一次决策帧”。

## 3. 输入源清洗与归一化

设备二输入源遵循同一个约定：`feed.poll(sim_time)` 返回：

```python
{
    "enemies": [...],
    "friendlies": [...],
    "meta": {...},
    "events": [...]
}
```

### `perception/ingest.py::RadarIngestService.poll(sim_time)`

职责：统一输入端口的薄封装。

执行逻辑：

1. 调用底层 feed 的 `poll(sim_time)`。
2. 用 `RadarTrackFrame.from_snapshot(...)` 把字典收口成 `RadarTrackFrame`。

注意：当前 `simulation/main.py::_sync_teacher_data()` 直接调用 `self.feed.poll(...)`。`RadarIngestService` 更像接口层/测试层，说明未来新输入源应该满足什么形状。

### `perception/radar_feed.py::TeacherDataFeed.poll(sim_time)`

职责：从设备一 Redis 态势源读取一帧，并归一化成设备二可消费的敌我航迹。

执行顺序：

```text
TeacherDataFeed.poll()
  -> _collect_live_sources()
  -> _collect_hash_sources()      # hash 格式时
  -> _parse_value()
  -> _normalize_tracks()
```

关键操作：

1. `_collect_live_sources()` 只负责从 Redis 取原始 key/value、set、hash，不判断业务含义。
2. `_collect_hash_sources()` 兼容 `enemy:set`、`uav:set`、`enemy:status:*`、`uav:status:*` 等 hash 输入。
3. `_parse_value()` 把字符串数字、JSON、`key=value` 文本转成 Python 对象。
4. `_normalize_tracks(...)` 按敌我前缀和字段分组，提取坐标、速度、姿态、状态，把经纬度或外部坐标投影为设备二本地坐标。
5. 敌方目标会经过 `perception/enemy_association.py::LocalEnemyAssociator.associate()` 做稳定 ID 关联，降低上游临时编号变化对任务分配的影响。

### `perception/udp_gateway.py::TeacherUDPFeed.poll(sim_time)`

职责：从 UDP 输入缓存读取设备一态势帧。

它与 Redis feed 的下游输出形状一致，最终也返回 `enemies/friendlies/meta/events`。因此后续 `_sync_teacher_data()` 不需要关心数据来自 Redis 还是 UDP。

## 4. 输入帧写入环境状态

### `simulation/main.py::_upsert_live_enemies(tracks)`

职责：把敌方航迹写入 `env.enemies`。

执行逻辑：

1. 遍历输入 `tracks`。
2. 用 `track["external_id"]` 查找已有敌机。
3. 如果不存在，调用 `_create_live_enemy(track)` 新建设备二内部敌机。
4. 如果存在，调用 `_apply_track_to_enemy(enemy, track)` 刷新坐标、速度、高度、姿态、质量、丢失状态等。
5. 本帧没出现的历史 teacher 敌机标记为 `stale=True`。

输出状态：

```text
env.enemies[*].id              # 设备二内部目标 ID
env.enemies[*].external_id     # 设备一/输入源目标 ID
env.enemies[*].x/y/z           # 本地坐标
env.enemies[*].state           # APPROACHING / DESTROYED / PENETRATED 等
env.enemies[*].detected        # 是否已进入可拦截发现状态
env.enemies[*].lost/stale      # 航迹丢失/延迟
```

### `simulation/main.py::_create_live_enemy(track)`

职责：把一条新航迹转换成设备二敌机对象。

关键字段：

1. 分配 `enemy["id"] = self.next_enemy_id`。
2. 初始 `enemy["state"] = EState.APPROACHING`。
3. 初始 `enemy["detected"] = False`，后续由 `_update_enemy_detection()` 判断是否发现。
4. 保存 `external_id`、`track_quality`、`classification_confidence`、`frame`、`raw_track`。

### `simulation/main.py::_apply_track_to_enemy(enemy, track)`

职责：刷新已有敌机对象。

关键操作：

1. 更新 `x/y/z/vz/heading/speed`。
2. 更新 `track_quality`、`classification_confidence`、`stale/lost/age`。
3. 重新计算姿态。
4. 如果目标未被摧毁/突防，把状态恢复为 `EState.APPROACHING`。

### `simulation/main.py::_sync_live_friendlies(tracks)`

职责：把设备一上报的己方真实 UAV 状态写入 `env.interceptors`。

关键操作：

1. 用 `_map_uav_track(track["external_id"])` 把外部 UAV ID 映射到设备二内部拦截机。
2. 标记 `it["external_controlled"] = True`。
3. 写入 `reported_x/y/z`、`reported_speed`、`reported_heading`、`reported_at`、`raw_track` 等。
4. 后续 `PlanFrame` 的 `uav_snapshot` 和路径规划会读取这些状态。

## 5. 设备二一次决策 tick

### `simulation/main.py::InterceptionEnvironment.step(dt)`

输入同步后，`step()` 继续执行决策流程。

主要顺序：

```text
step(dt)
  -> _update_llm_reserved_pool()
  -> analyst.update_situation(...)
  -> _update_enemy_detection()
  -> _assign_idle_searchers_to_targets()
  -> _maybe_auto_llm_interference_replan()
  -> _split_targets_by_mode(...)
  -> assigner.update(...)              # hit / hybrid 撞击拦截
  -> _update_barrier_assignments(...)  # net / hybrid 列阵扯网
  -> _update_net_assignments(...)      # legacy-net 旧网阻
  -> _update_launch_states()
  -> _update_demo_interference()
  -> _move_interceptors(dt)
  -> 本地完成判定
```

### `simulation/main.py::_update_enemy_detection()`

职责：判断敌机是否进入发现/接战条件。

结果：

1. 把符合条件的敌机 `enemy["detected"]` 置为 `True`。
2. 记录 `enemy["detect_time"]`。
3. 后续任务分配只处理 `detected` 的目标。

### `simulation/main.py::_split_targets_by_mode(engageable_enemies)`

职责：根据目标类型、拦截模式和场景策略，把可接战目标拆成不同任务队列。

输出：

```text
hit_targets      # 撞击拦截目标
barrier_targets  # 列阵/扯网目标
net_targets      # legacy-net 目标
```

## 6. 任务分配

### 撞击拦截：`decision/cooperation.py::InterceptionAssigner.update(interceptors, enemies, current_time)`

调用方：`simulation/main.py::step()`。

职责：为 `hit` / `hybrid` 模式下的目标分配主拦截机和随动机。

执行顺序：

```text
InterceptionAssigner.update()
  -> StableRetaskPolicy.reconcile(...)
  -> _assign_primary(...)
  -> _assign_follower(...)
  -> compute_poi(...)
```

关键操作：

1. 过滤有效目标：必须是 `APPROACHING/MANEUVERING`、`detected=True`、且未 `lost`。
2. `decision/reassignment.py::StableRetaskPolicy.reconcile(...)` 清理失效绑定，避免目标消失、飞机故障后继续占用任务。
3. 对每个目标调用 `_assign_primary(...)`。
4. 条件允许时调用 `_assign_follower(...)` 补随动备份机。
5. 对已分配飞机调用 `compute_poi(...)` 计算预测拦截点和 ETA，写入 `it["poi"]`、`it["poi_time"]`、`assignments[eid]["poi"]`。

### `decision/cooperation.py::_assign_primary(interceptors, enemy, ct)`

职责：为某个敌机挑选主拦截机。

选择策略：

1. 在 `STANDBY/RETURNING`、无目标、未受干扰、未被 LLM 保留、设备一执行侧可用的 UAV 中筛选候选。
2. 优先选择 POI 可达且在防线前的 UAV。
3. 其次选择能追上的紧急前出 UAV。
4. 最后选择距离最近 UAV 直扑。

写回状态：

```text
best["state"] = IState.LAUNCHING
best["target_id"] = enemy["id"]
best["role"] = IRole.PRIMARY
best["launch_time"] = ct + launch_delay
best["target_z"] = enemy["z"]
assignments[enemy_id]["primary"] = best["id"]
assignments[enemy_id]["poi"] = best_poi
assignments[enemy_id]["eta"] = best_eta
```

### `decision/cooperation.py::_assign_follower(interceptors, enemy, asgn)`

职责：按压力、目标类型、置信度、可用飞机数量决定是否派随动机。

写回状态：

```text
follower["state"] = IState.LAUNCHING
follower["target_id"] = enemy["id"]
follower["role"] = IRole.FOLLOWER
assignments[enemy_id]["follower"] = follower["id"]
```

### 列阵/扯网：`simulation/main.py::_update_barrier_assignments(targets)`

调用方：`step()` 中 `intercept_mode in ("net", "hybrid")` 时执行。

职责：为扯网/列阵目标生成多机编组、网面槽位和任务绑定。

结果会写入：

```text
it["target_id"]
it["barrier_slot"]
it["formation_role"]
it["state"] = IState.LAUNCHING / INTERCEPTING
```

### 旧网阻：`simulation/main.py::_update_net_assignments(targets)`

调用方：`step()` 中 `intercept_mode == "legacy-net"` 时执行。

职责：保留旧网阻模式的多机编组分配。

结果会写入：

```text
it["target_id"]
it["net_slot"]
it["formation_role"]
```

## 7. 起飞、路径规划与运动推进

### `simulation/main.py::_update_launch_states()`

职责：处理处于 `IState.LAUNCHING` 的 UAV。

执行逻辑：

1. 如果还在 `CFG.LAUNCH_DELAY` 内，保持等待放行。
2. 调用 `self.deconfliction.can_release_launch(it)` 做起飞走廊检查。
3. 放行后设置速度为 `CFG.INTERCEPTOR_SPEED`。
4. 根据角色切换状态：
   - 主拦截：`IState.INTERCEPTING`
   - 随动：`IState.FOLLOWING`
   - 列阵/网阻成员：`IState.INTERCEPTING`
5. 调用 `_update_route_plan(it, target, "起飞后进入设备一规划航线")` 刷新路径。

### `simulation/main.py::_move_interceptors(dt)`

职责：根据当前任务状态推进己方 UAV，并刷新后续输出帧要使用的路径/动作。

调度顺序：

```text
_move_interceptors(dt)
  -> _guide_barrier_member(...)  # barrier_slot
  -> _guide_net_member(...)      # net_slot
  -> _guide_primary(...)         # INTERCEPTING
  -> _guide_follower(...)        # FOLLOWING
  -> _guide_returning(...)       # RETURNING
  -> deconfliction.deconflict_interceptors()
```

真实飞控接入时，如果 UAV 是 `external_controlled`，函数开始会保存设备一上报位置，末尾 `_restore_authoritative_friendlies(...)` 恢复权威位置。也就是说设备二仍会计算航点/意图，但不把本地仿真坐标当作真实执行结果覆盖设备一上报。

### `simulation/main.py::_plan_local_motion(it, desired_point, desired_speed, mission_ctx)`

职责：把任务层的期望点交给局部规划器，得到可执行的 `command_point`。

调用链：

```text
_guide_primary/_guide_follower/...
  -> _plan_local_motion(...)
  -> decision/deconfliction.py::DeconflictionController.plan_local_motion(...)
```

### `decision/deconfliction.py::DeconflictionController.plan_local_motion(...)`

职责：局部航线约束和避碰。

处理内容：

1. 限制期望点在战场范围和高度上限内。
2. 检查全局强制避让指令。
3. 起飞/返航交通管制。
4. 禁飞区/扯网区绕飞。
5. 局部空域过密时等待放行。
6. RVO 微调速度和指令点。
7. 平滑指令点，减少抖动。

输出 `LocalPlan`，关键字段包括：

```text
command_point
speed_cap
target_z
hold_reason
avoid_mode
allow_terminal_direct
```

### `simulation/main.py::_execute_local_plan(it, dt, plan, enemy=None)`

职责：把 `LocalPlan` 转成实际运动。

执行逻辑：

1. 如果允许终端直导，调用 `ProNav.command(it, enemy)`。
2. 否则调用 `ProNav.guide_point(it, plan.command_point)`。
3. 调用 `_advance_interceptor_motion(...)` 更新航向和位置。

### `decision/deconfliction.py::DeconflictionController.deconflict_interceptors()`

职责：全局强制避撞。

它在每次 `_move_interceptors()` 末尾执行，处理已经过近或预测将冲突的己方 UAV，必要时写入减速、高度调整或强制推开指令。

## 8. 任务完成判定

### 本地仿真完成判定

如果当前不是权威真实航迹模式，即 `_uses_authoritative_live_tracks()` 为 `False`，`step()` 会在本地模拟敌机运动并做完成判定：

```text
step(dt)
  -> _move_enemies(dt)
  -> _check_intercepts()
  -> _check_barrier_capture()
  -> _check_net_capture()
  -> _check_penetration()
  -> _consume_fuel(dt)
  -> _update_mission_labels()
  -> _check_done()
```

### `simulation/main.py::_check_intercepts()`

职责：撞击拦截命中判定。

条件满足时：

1. 敌机 `enemy["state"] = EState.DESTROYED`。
2. 撞击机 `it["state"] = IState.DESTROYED`。
3. 更新 `stats["kills"]`、`stats["our_losses"]`。
4. 释放同目标的随动伙伴，让其返航。

### `simulation/main.py::_check_barrier_capture()`

职责：列阵/扯网捕获判定。

成功时会把目标置为已处置状态，并释放编队任务。

### `simulation/main.py::_check_net_capture()`

职责：旧网阻模式捕获判定。

### `simulation/main.py::_check_penetration()`

职责：判断敌机是否越过防线。

如果敌机 `y >= CFG.INTERCEPT_FAIL_LINE`：

```text
enemy["state"] = EState.PENETRATED
stats["penetrations"] += 1
```

### `simulation/main.py::_check_done()`

职责：判断整个任务是否结束。

演示模式下，所有敌机都 `DESTROYED/PENETRATED` 且所有波次已生成后：

```text
self.done = True
self.success = stats["penetrations"] == 0
```

真实两设备联调时，实际无人机是否完成动作通常以设备一执行侧状态/回执为准；设备二本地完成判定主要用于仿真和无真实飞控接入的闭环验证。

## 9. 决策帧回发设备一

### `station/exporter.py::PlannerExporter.maybe_publish(env, force=False)`

调用方：`simulation/main.py::run_demo()` 主循环末尾。

职责：把当前环境状态构造成设备一可消费的决策输出帧，并发送出去。

执行顺序：

```text
maybe_publish(env)
  -> _poll_feedback(env)
  -> _input_frame_key(env)
  -> _should_publish(now, input_key)
  -> PlanFrameBuilder.build(...)
  -> _payload_from_frame(frame)
  -> _send_frame(payload, now, logs)
  -> station_bridge.forward(frame)     # 可选
  -> debug_redis.publish_text(...)     # 可选
  -> _poll_feedback(env)
```

触发策略：

1. 默认 `publish_policy = "input_frame"`。
2. `_input_frame_key(env)` 从 `env.last_live_packet_meta` 取 `frame`、`seq` 或 `timestamp`。
3. 只有输入帧 key 变化时才发布新决策帧。
4. 发送成功后才记录 `last_published_input_key`，避免发送失败时误认为该输入帧已经闭环。

### `station/contracts.py::PlanFrameBuilder.build(env, options, plan_seq, timestamp_ms)`

职责：把设备二内部状态转换成完整 `PlanFrame`。

执行逻辑：

1. 生成 `frame_id`、`radar_frame_id`、`plan_seq`、`timestamp_ms`。
2. 遍历 `env.interceptors` 中可导出的 UAV。
3. 用 `_get_target_for_uav(env, it)` 找到 UAV 当前目标。
4. 计算 `mission_type`、`role`、`formation_role`、`group_id`。
5. 调用 `_build_assignment(...)` 生成任务绑定信息。
6. 调用 `_build_route(...)` 生成路径点、下一指令点和低层控制意图。
7. 汇总 `assignments`、`routes`、`groups`、`situation_alert` 等字段。

### `station/contracts.py::_build_assignment(...)`

职责：生成“谁打谁、什么任务、什么角色”的任务绑定。

典型字段：

```text
assignment_id
assignment_epoch
uav_id / drone_id
```

## 10. 设备一回执与重分配

### `station/exporter.py::_poll_feedback(env)`

职责：从 socket 等通道拉取设备一回执，然后交给 feedback handler。

下游：

```text
_poll_feedback(env)
  -> station/feedback.py::Device3FeedbackHandler.process(env, events)
```

### `station/feedback.py::Device3FeedbackHandler.process(env, events)`

职责：处理设备一执行侧回执并写回设备二环境。

支持消息：

1. `plan_ack`：设备一是否接收该决策帧。
2. `execution_report`：设备一执行结果。
3. `uav_status`：设备一上报的 UAV 实时执行状态缓存。

### `station/feedback.py::_handle_execution_report(env, event)`

职责：处理执行失败/中止/完成等状态。

如果 `status in ("failed", "aborted")`：

1. 找到对应 UAV。
2. 标记 `it["device3_temporarily_unavailable"] = True`。
3. 设置冷却时间 `it["device3_failed_until"]`。
4. 调用 `_release_failed_binding(env, it)` 释放该机任务。
5. 调用 `_trigger_reassignment(env)`，最终触发 `simulation/main.py::_force_task_reassignment(...)`。

如果 `status in ("completed", "engaging", "en_route", "executing")`：

1. 清除临时不可用标记。
2. 保留最新执行状态缓存。

## 13. 调试定位提示

常见日志标签：

```text
[DATA]   输入源连接、切换实时数据、诊断信息
[RADAR]  新建敌方轨迹
[ASGN]   撞击拦截任务分配
[BARRIER]列阵/扯网任务分配
[NET]    legacy-net 任务分配
[PLAN]   决策帧发送、回执、执行失败
[LOST]   航迹丢失
[REACQ]  航迹重获
[FAIL]   敌机突防
```

排查某架 UAV 为什么没有动作时，优先查：

1. 输入帧里是否有对应目标：`TeacherDataFeed.poll()` 输出。
2. 目标是否进入 `enemy["detected"] = True`：`_update_enemy_detection()`。
3. UAV 是否被绑定：`assigner.assignments` 或 `it["target_id"]`。
4. UAV 是否仍在 `LAUNCHING` 等待放行：`_update_launch_states()`。
5. 是否被局部规划器等待/绕飞：`it["local_hold_reason"]`、`it["local_avoid_mode"]`。
6. 输出帧里是否出现该 UAV：`PlanFrameBuilder.build()` 的 `assignments/routes`。
7. 设备一是否拒收或执行失败：`Device3FeedbackHandler.process()`。
