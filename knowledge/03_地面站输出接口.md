# 03 设备二决策输出接口

最后更新：2026-07-14

## 目标

设备二把决策结果回发给设备一。输出要同时满足：

1. 设备一指挥大屏需要一句话态势、任务绑定、敌我状态摘要。
2. 设备一飞控执行侧需要每架无人机的具体动作、下一指令点、短路径点、速度和控制意图。

核心原则：**设备二仍以 `PlanFrame` 作为完整决策帧，设备一主链路默认消费从 `PlanFrame` 裁剪出的 `decision_output_frame`。两者同源，不重新分配、不重新规划。**

## 代码落点

| 文件 | 职责 | 主要函数 |
| --- | --- | --- |
| `station/contracts.py` | 生成完整 `PlanFrame` | `PlanFrameBuilder.build()`、`_build_assignment()`、`_build_route()` |
| `station/query.py` | 从 `PlanFrame` 裁剪设备一视图 | `decision_output_frame_from_plan_frame()`、`station_flight_commands_from_frame()` |
| `station/exporter.py` | 按 `core.common.PLAN_EXPORT` 回发决策帧 | `PlannerExporter.maybe_publish()`、`_payload_from_frame()`、`_send_frame()` |
| `station/socket_client.py` | TCP JSON Lines 收发 | `send_json()`、`poll_feedback()` |
| `station/feedback.py` | 处理设备一执行回执 | `Device3FeedbackHandler.process()` |
| `station/plan_bridge.py` | 历史地面站旁路转接包 | `build_station_transfer_packet()`、`StationPlanBridge.forward()` |
| `station/output.py` | 决策输出薄接口 | `StationOutputService.from_env()`、`from_plan_frame()` |

## 输出调用回路

```text
simulation/main.py 主循环
  -> PlannerExporter.maybe_publish(env)
    -> _poll_feedback(env) 先读取设备一回执
    -> 根据 PLAN_EXPORT["publish_policy"] 判断是否需要发帧
       - input_frame：设备一输入帧变化才发送
       - interval：按 publish_interval 周期发送
       - input_frame_or_interval：输入帧变化立即发，否则按周期兜底
    -> PlanFrameBuilder.build(env, options, plan_seq, timestamp_ms)
    -> decision_output_frame_from_plan_frame(frame)
    -> _send_frame() 用 PlannerSocketClient.send_json() 发 TCP JSON Lines
    -> StationPlanBridge.forward() 可选历史旁路转接
    -> debug_redis.publish_text() 可选写实际发送载荷的 Redis 调试镜像
    -> _poll_feedback(env) 再读取一次快速回执
```

## 当前主链路配置

`core/common.py` 中默认保留关闭发布：

```python
PLAN_EXPORT = {
    "enabled": False,
    "transport": "tcp_json_lines",
    "publish_policy": "input_frame",
    "output_frame_type": "decision_output_frame",
    "socket_host": "127.0.0.1",
    "socket_port": 7001,
}
```

联调时开启 `enabled` 并把 `socket_host/socket_port` 改成设备一接收端地址。

## `PlanFrame` 完整帧

`PlanFrameBuilder.build()` 生成完整决策帧，包含：

| 字段 | 含义 |
| --- | --- |
| `radar_frame_id` | 本次决策基于的设备一输入帧号 |
| `situation_alert` | 一句话态势总结 |
| `assignment_plan.assignments[]` | 单机任务绑定，回答“谁打谁、什么角色” |
| `route_plan.routes[]` | 单机路径和动作，回答“怎么飞、做什么” |
| `groups[]` | 多机协同编组 |

## `decision_output_frame` 精简帧

`station.query.decision_output_frame_from_plan_frame(frame)` 从完整帧裁剪：

```json
{
  "msg_type": "decision_output_frame",
  "schema_version": "decision_output.v1",
  "radar_frame_id": 1001,
  "plan_seq": 23,
  "timestamp_ms": 1783766400000,
  "situation_alert": "当前发现2个活动目标，6架我方无人机可用，3个任务绑定。",
  "commands": []
}
```

`commands[]` 每条对应一架己方无人机：

| 字段 | 来源 | 含义 |
| --- | --- | --- |
| `uav_id/drone_id` | assignment/route | 设备一执行主体 |
| `target_id` | assignment | 当前绑定的敌方目标 |
| `assignment_id/assignment_epoch` | assignment | 单机任务 ID 和任务代数 |
| `mission_type` | assignment | 拦截、返航、待重分配、不可用等 |
| `role/formation_role` | assignment | 主拦截、随动、编队槽位 |
| `actions` | route.control_intent.low_level_actions | 解锁、起飞、切模式、上传航点或等待 |
| `next_command_point` | route | 下一指令点 |
| `waypoints` | route | 短路径点 |
| `speed_mps` | route | 建议速度 |

## 回执闭环

```text
设备一
  -> TCP JSON Lines 回传 PlanAck / ExecutionReport / UavStatus
  -> PlannerSocketClient.poll_feedback()
  -> PlannerExporter._poll_feedback(env)
  -> Device3FeedbackHandler.process(env, events)
    -> ACK：记录接收/上传状态
    -> failed/aborted：标记 UAV 临时不可用，释放任务绑定，触发重分配
    -> UavStatus：同步外部执行状态
```

`Device3FeedbackHandler` 是历史类名，当前语义是“设备一执行回执处理器”。内部状态键如 `device3_temporarily_unavailable` 暂不重命名，避免破坏既有分配器逻辑。

## 边界约束

- 输出层只做裁剪、校验、发送和回执处理，不能修改设备二的内部任务分配结果。
- 如果需要新增设备一字段，优先从 `PlanFrame` 裁剪或在 `PlanFrameBuilder` 中补快照，不另建第二套算法。
- `assignment.target_snapshot` 是敌方状态快照，`route.uav_snapshot` 是己方状态快照。
