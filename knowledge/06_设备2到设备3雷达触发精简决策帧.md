# 06 设备二按设备一输入帧触发的精简决策帧

最后更新：2026-07-14

> 文件名沿用旧“设备2到设备3”命名，避免引用断裂；当前真实语义是“设备二按设备一输入帧触发回发精简决策帧”。

## 1. 文档目的

本文描述设备一最适合直接消费的精简决策帧，不展开完整 `PlanFrame`。

目标是：设备二每接收到一组设备一态势数据并完成一次决策后，向设备一回发一帧决策结果。该帧包含：

1. 一句话态势总结。
2. 己方无人机谁绑定敌方无人机谁。
3. 每架无人机为了执行任务需要做什么动作，例如解锁、起飞、切模式、上传航点或等待。
4. 下一指令点和短路径点。

该精简帧由 `station.query.decision_output_frame_from_plan_frame(frame)` 从现有 `PlanFrame` 裁剪得到，不另造一套分配或规划逻辑。

## 2. 触发时机

| 项目 | 说明 |
| --- | --- |
| 输入触发 | 设备二接收到一组设备一态势数据 |
| 决策处理 | 设备二完成目标更新、任务分配、路径规划和态势总结 |
| 输出动作 | 设备二向设备一发送一帧精简决策帧 |
| 一帧含义 | 同一个 `radar_frame_id` 下的当前任务绑定和下一步控制建议 |
| 发送格式 | TCP JSON Lines，一行一个 JSON 对象，以 `\n` 结尾 |
| 去重依据 | `env.last_live_packet_meta` 中的 `device_id/frame/seq/timestamp` |

`core/common.py` 默认配置：

```python
PLAN_EXPORT = {
    "publish_policy": "input_frame",
    "output_frame_type": "decision_output_frame",
}
```

## 4. 顶层字段

| 字段名称 | 类型 | 取值/说明 | 现有来源 |
| --- | --- | --- | --- |
| `msg_type` | string | 固定为 `decision_output_frame` | 精简帧消息名 |
| `schema_version` | string | 固定为 `decision_output.v1` | 精简帧版本 |
| `source_frame_id` | string | 来源完整帧 ID | `PlanFrame.frame_id` |
| `radar_frame_id` | int/null | 当前决策基于哪一组设备一输入数据 | `PlanFrame.radar_frame_id` |
| `plan_seq` | int | 设备二决策输出序号 | `PlanFrame.plan_seq` |
| `timestamp_ms` | int64 | 设备二生成该帧的时间戳 | `PlanFrame.timestamp_ms` |
| `valid_until_ms` | int64 | 决策帧有效截止时间 | `PlanFrame.valid_until_ms` |
| `situation_alert` | string | 一句话态势总结 | `PlanFrame.situation_alert` |
| `binding_ok` | bool | assignment/route 是否绑定一致 | 裁剪校验 |
| `binding_errors` | array | 绑定错误列表 | 裁剪校验 |
| `commands` | array | 单架无人机决策指令列表 | assignment + route 合并 |

## 5. 单架无人机指令字段

| 字段名称 | 类型 | 取值/说明 | 现有来源 |
| --- | --- | --- | --- |
| `uav_id` | string | 己方无人机字符串 ID，例如 `uav_01` | assignment/route |
| `drone_id` | int | 设备一/飞控使用的数字无人机 ID | assignment/route |
| `target_id` | string/null | 绑定的敌方目标 ID；返航或等待时可为空 | assignment |
| `assignment_id` | string | 单机任务绑定 ID，用于回执和去重 | assignment |
| `assignment_epoch` | int | 同一 UAV 任务代数；变化表示切换任务 | assignment |
| `route_id` | string | 当前路径 ID | route |
| `mission_type` | string | `intercept`、`return_home`、`retask_pending` 等 | assignment |
| `role` | string | `primary`、`backup`、`reserve` | assignment |
| `formation_role` | string/null | 编队槽位 | assignment |
| `status` | string | 路径状态 | route |
| `failure_reason` | string | 失败或等待原因 | route |
| `speed_mps` | float | 建议速度 | route |
| `actions` | array | 当前 UAV 要执行的动作列表 | `control_intent.low_level_actions[]` |
| `control_intent` | string | 高层意图，如 `execute_intercept_route` | route |
| `next_command_point` | object/null | 下一指令点 | route |
| `waypoints` | array | 短路径点 | route |

## 6. 设备一处理流程

1. 按行读取 TCP JSON Lines。
2. 解析 `msg_type=decision_output_frame` 的消息。
3. 用 `radar_frame_id` 对齐当前态势输入帧。
4. 显示 `situation_alert`。
5. 遍历 `commands[]`。
6. 根据 `uav_id/drone_id` 找到己方无人机。
7. 根据 `target_id` 显示或绑定敌方目标。
8. 根据 `actions[].command` 执行解锁、起飞、切模式、上传航点或等待。
9. 根据 `next_command_point` / `waypoints` 执行下一步飞行控制。

## 7. 绑定规则

1. 同一 `uav_id` 和 `assignment_epoch` 不变，表示仍是同一任务。
2. `assignment_epoch` 递增，表示该 UAV 已切换到新任务。
3. `target_id` 变化，设备一应按新目标处理。
4. `target_id` 为空且 `mission_type=return_home`，表示无目标返航。
5. `mission_type=retask_pending`，表示设备二正在等待下一次重分配结果。
