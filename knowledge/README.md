# knowledge 阅读索引

最后更新：2026-08-20

本目录按流程编号组织。当前联调边界已由旧“三设备”调整为“两设备”：

1. **设备一：郭老师设备/地面统筹设备**，负责接收雷达数据、清理过滤成当前战场态势、接收设备二决策帧、实际操控无人机并在指挥大屏显示。
2. **设备二：我方决策外挂**，即本仓库主体，负责读取设备一给出的战场态势，运行任务分配、路径规划和态势总结，并把决策帧回发设备一。

## 编号流程文档

1. `00_项目总览.md`：两设备边界与主链路。
2. `01_雷达数据输入接口.md`：设备一清理后的战场态势进入设备二的处理接口。
3. `02_设备2决策流程接口.md`：任务分配、路径规划、态势警报的流程接口。
4. `03_地面站输出接口.md`：设备二回发设备一的完整帧、精简决策帧和飞控指令视图。
5. `04_端到端联调流程.md`：从设备一态势输入到设备二决策回发的联调步骤。
6. `05_设备2到设备3决策输出通信帧.md`：旧名保留，实际记录完整 `PlanFrame` 决策输出字段。
7. `06_设备2到设备3雷达触发精简决策帧.md`：旧名保留，实际记录按设备一输入帧触发的精简 `decision_output_frame`。
8. `07_雷达入侵到任务完成代码数据流.md`：按代码执行顺序说明从雷达入侵输入、任务分配、路径规划到决策回发/完成闭环的数据流。
9. `08_设备二给设备一反馈内容.md`：说明设备二发出决策帧后，设备一可回给设备二的回执、执行报告和 UAV 状态反馈。
10. `09_大小模型融合决策改造思路.md`：梳理地面大模型、机载小模型、传统算法兜底和知识蒸馏闭环的工程改造路线。
11. `10_本地大模型决策现状.md`：分析当前工程是否已经实现真正的大模型决策，以及还缺哪些底座能力。
