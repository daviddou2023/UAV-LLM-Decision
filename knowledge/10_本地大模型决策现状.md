# 10 本地大模型决策现状

最后更新：2026-08-20

## 结论

当前工程**没有实现真正的大模型决策底座**。

现有代码里，大模型已经参与了战场态势播报、对话回复和少量任务约束解析，但它**还没有直接输出高层动作意图、行为策略或子任务序列**，也**没有接管任务分配与路径规划主流程**。真正的决策仍由传统算法完成。

换句话说：

- 有 LLM 参与。
- 有 LLM 约束影响传统分配器。
- 有 LLM 文本建议触发少量派机行为。
- 但没有形成“LLM -> 高层决策 -> 控制层执行 -> 子任务序列”的完整闭环。

## 现有实现到了哪一步

### 1. LLM 已在做什么

`decision/llm_kit.py::BattlefieldAnalyst` 已接入本地模型服务，作用是：

- 生成一句话战场态势。
- 回答指挥员自然语言问题。
- 在模型不可用时回退到规则文本。

它的输入是当前敌我列表，输出主要是自然语言文本，不是结构化决策对象。

### 2. LLM 约束在做什么

`decision/llm_task_constraints.py` 和 `simulation/main.py::_apply_llm_task_constraints_from_command()` 已能把口令解析成结构化约束，例如：

- `reserve_count`
- `target_priority`
- `preferred_sector`
- `avoid_jam`
- `max_active_count`

这些约束会同步到 `InterceptionAssigner.task_constraints`，影响传统分配器的排序、保留机数量和出动上限。

这属于“LLM 影响传统算法参数”，不是“LLM 自主决策”。

### 3. 真正的任务分配仍是谁在做

`simulation/main.py::step(dt)` 里，核心流程仍然是：

1. 同步设备一输入。
2. 更新 LLM 约束。
3. 调用 `decision/cooperation.py::InterceptionAssigner.update()` 做撞击模式分配。
4. 调用 `_update_barrier_assignments()` / `_update_net_assignments()` 做编组。
5. 调用 `decision/deconfliction.py::DeconflictionController.plan_local_motion()` 做局部避碰和路径修正。
6. 调用 `_move_interceptors(dt)` 刷新 `path_plan`。
7. 由 `station/contracts.py::PlanFrameBuilder.build()` 输出 `PlanFrame`。

所以当前“主决策权”还是在传统算法链路里。

### 4. 输出层有没有真正的大模型决策

没有。

`station/contracts.py` 里的 `control_intent` 是由 `mission_type` 和当前路径状态派生出的飞控意图，例如：

- `intercept`
- `return_home`
- `hold_for_retask`
- `hold_for_recovery`

这些意图是传统状态机和路径结果的编码，不是大模型产出的“行为策略”。

`station/query.py` 只是把 `PlanFrame` 裁剪成 `decision_output_frame`，没有新增决策能力。

## 现有代码中唯一接近“LLM 决策”的地方

`simulation/main.py::_apply_assistant_action(chat_msg)` 会根据 `BattlefieldAnalyst` 的聊天回复内容，触发一次很窄的派机动作：

- 先通过字符串规则判断是否像“建议派机”。
- 再调用 `_dispatch_one_interceptor()` 派出一架无人机。

但这仍然不是大模型真正输出了高层策略：

- 它依赖文本关键字。
- 它只决定“是否尝试派一架机”。
- 它不输出任务序列、行为策略、动作图、分层子任务，也不直接控制路径规划。

因此，这条链路只能算“文本建议驱动的局部动作”，不能算真正的大模型决策底座。

## 现阶段缺失什么

要实现你要的底座，当前工程至少还缺以下能力：

### 1. 结构化高层决策接口

需要新增一层明确的决策抽象，让大模型输出的不是自然语言，而是可校验的结构化结果，例如：

- 任务优先级
- 目标绑定
- 行为策略
- 子任务序列
- 动作意图
- 路径意图

现在没有这样的统一对象。

### 2. 决策校验层

大模型输出不能直接进控制层，必须先校验：

- UAV 编号是否存在。
- 目标编号是否存在。
- 任务是否冲突。
- 路径意图是否穿越禁飞/干扰区。
- 输出是否超出当前机群资源。

当前只有很少的协议字段校验，没有完整的模型输出校验层。

### 3. 决策策略调度层

当前 `simulation/main.py` 直接编排传统算法。
要让大模型做高层决策，需要增加一层策略调度：

- 大模型策略
- 规则策略
- 失效回退策略

现在没有统一的 `DecisionPolicy` 之类入口。

### 4. 决策日志和样本采集

如果后续要做本地大模型真正决策，再做大小模型融合，必须先能采集：

- 输入态势
- 模型输出
- 传统算法输出
- 最终执行结果

当前工程没有专门的决策样本闭环。

### 5. 链路/干扰状态与模型自治切换

你提到的“地面大模型 + 上机小模型”场景，需要明确：

- 正常连接时谁做高层决策。
- 干扰后谁接管。
- 何时恢复地面全局决策。

当前干扰逻辑已经存在，但它主要服务于仿真和规则重规划，不是正式的模型自治切换机制。

## 建议怎么改，才算搭起真正的大模型决策底座

### 第一层：定义统一决策对象

新增一个内部结构，把大模型输出固定成可校验结果，例如：

- `DecisionStateSnapshot`
- `DecisionProposal`
- `DecisionContext`

核心要求是：大模型输出必须先落成结构化对象，再进入控制层。

### 第二层：把传统算法包装成默认策略

先不要替换现有分配器和路径规划，而是把它们包装成默认策略：

- 规则策略负责现在的行为。
- 大模型策略以后可替换。
- 失败时回退规则策略。

这样能保住现有联调链路。

### 第三层：让大模型输出高层行为策略

大模型先只输出高层内容，不直接输出飞控命令：

- 先打谁。
- 采用什么任务模式。
- 需要保留多少机。
- 是否绕避干扰区。
- 是否返航、等待、搜索、重分配。

低层路径和避碰仍交给传统算法。

### 第四层：把输出接回现有 `PlanFrame`

最终还是要复用现有输出链路：

- 大模型决定高层策略。
- 传统算法把它落成 `target_id / role / poi / path_plan`。
- `PlanFrameBuilder` 继续生成完整帧。
- `decision_output_frame` 继续作为设备一消费帧。

这能保证协议稳定。

### 第五层：加入决策日志

在不改设备一协议的前提下，先把每帧的：

- 输入
- 决策
- 约束
- 执行结果

记录下来，后续才能做蒸馏和回放评估。

## 当前工程的真实状态

一句话：

**现在是“LLM 做态势文本和约束提示，传统算法做真正决策”。**

还不是：

**“LLM 做高层决策，传统算法做低层执行”**。

要达到后者，需要先补结构化决策对象、校验层、策略层和样本采集闭环。
