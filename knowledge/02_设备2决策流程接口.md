# 02 设备二决策流程接口

最后更新：2026-07-14

## 目标

设备二根据设备一输入的当前战场态势完成四类输出能力：

1. **任务分配**：哪架己方无人机锁定哪个敌方无人机，使用直接撞击、列阵/扯网或网阻等方式。
2. **路径规划**：任务确定后，己方无人机如何飞到目标点，包括局部航点、速度、绕飞、避碰和等待放行。
3. **单机动作建议**：每架无人机当前建议执行的动作，如解锁、起飞、切模式、上传短航点或等待。
4. **态势总结**：根据当前战场数据生成一句话态势提示，供设备一指挥大屏显示参考。

## 代码落点

| 文件 | 职责 | 主要函数 |
| --- | --- | --- |
| `decision/pipeline.py` | 决策流程薄接口 | `DecisionPipelineService.tick()`、`build_plan_frame()` |
| `simulation/main.py` | 决策主循环编排 | `InterceptionEnvironment.step(dt)`、`_move_interceptors()` |
| `decision/cooperation.py` | 撞击拦截任务分配 | `InterceptionAssigner.update()` |
| `decision/deconfliction.py` | 局部路径规划、避碰、绕飞 | `DeconflictionController.plan_local_motion()`、`deconflict_interceptors()` |
| `decision/reassignment.py` | 失败/回执后的重分配辅助 | `RetaskPolicy.reconcile()` 等 |
| `decision/llm_task_constraints.py` | LLM/指挥员约束解析 | 约束解析与应用辅助函数 |
| `decision/llm_kit.py` | 态势分析与对话封装 | `BattlefieldAnalyst.update_situation()` |
| `station/contracts.py` | 决策输出完整帧构造 | `PlanFrameBuilder.build()` |
| `station/query.py` | 精简决策帧裁剪 | `decision_output_frame_from_plan_frame()` |

## 外部调用接口

```python
from decision import DecisionPipelineService

pipeline = DecisionPipelineService(env)
result = pipeline.tick(dt=0.1, build_plan=True)
print(result.snapshot.alert)
plan_frame = result.plan_frame
```

`DecisionPipelineService` 不替代 `simulation/main.py`，只是把现有主循环封装成更清晰的设备二接口。

## 总调用回路

```text
DecisionPipelineService.tick(dt)
  -> env.step(dt)
    -> _pump_live_data() 同步设备一输入
    -> _update_llm_reserved_pool() 应用被 LLM/指挥员保留的 UAV
    -> analyst.update_situation() 生成态势日志/一句话提示
    -> _update_enemy_detection() 更新目标发现状态
    -> _split_targets_by_mode() 按任务模式拆分 hit/barrier/net 目标
    -> assigner.update() / _update_barrier_assignments() / _update_net_assignments()
    -> _update_launch_states() 处理起飞队列
    -> _move_interceptors(dt) 执行路径规划与运动更新
    -> 本地仿真判定/状态更新
  -> DecisionSnapshot.from_env(env)
  -> 可选 PlanFrameBuilder.build(env, ...)
  -> 可选 decision_output_frame_from_plan_frame(frame)
```

## 关键输出

| 输出 | 生成位置 | 用途 |
| --- | --- | --- |
| `DecisionSnapshot.assignments` | `decision/pipeline.py` | 测试/上层快速查看当前绑定 |
| `DecisionSnapshot.alert` | `DecisionSnapshot.from_env()` | 一句话战场态势 |
| `env.interceptors[*].path_plan` | `_move_interceptors()` | `station/contracts.py` 采样生成 `waypoints` |
| `PlanFrame.situation_alert` | `station/contracts.py::_situation_alert()` | 完整帧中的一句话态势 |
| `PlanFrame.assignment_plan` | `PlanFrameBuilder.build()` | 打谁、任务角色、目标快照 |
| `PlanFrame.route_plan` | `PlanFrameBuilder.build()` | 怎么飞、路径点、速度和动作意图 |
| `decision_output_frame.commands[]` | `station/query.py` | 设备一直接消费的单机决策指令 |

## 边界约束

- 决策层更新设备二内部环境状态，但不直接操控真实无人机。
- 飞控动作只表达为建议动作和路径点，设备一负责将其转换为真实飞控控制。
- LLM 建议不能绕过任务分配器直接改成另一套协议；必须落到现有环境状态或约束上。
- 发布触发不在决策算法内部做，由 `station/exporter.py` 根据设备一输入帧元数据统一控制。
