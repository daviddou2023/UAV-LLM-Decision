# 00 项目总览

最后更新：2026-07-14

本项目当前主要实现 **设备二：我方决策外挂**。系统边界已由旧“三设备”调整为两设备：

1. **设备一：郭老师设备/地面统筹设备**
   接收雷达数据，完成清理、过滤和战场态势汇总；把当前战场态势发送给设备二；收到设备二决策帧后，负责实际操控无人机运动并在指挥大屏显示。
2. **设备二：决策外挂**
   接收设备一给出的当前战场态势，完成目标处理、任务分配、路径规划和一句话态势总结；每收到一次设备一输入帧，就对应回发一帧决策结果。

旧文档和代码中出现的“设备3/地面站/station”多为历史命名。当前不改工程目录名，`station/` 继续作为“决策输出与兼容转接模块”使用；对端语义以设备一为准。

## 功能模块目录对应

| 功能模块 | 目录 | 说明 |
| --- | --- | --- |
| 态势输入 | `perception/` | 接收设备一清理后的雷达/外部航迹，归一化、稳定 ID 关联，同步进设备二环境 |
| 决策规划 | `decision/` | 设备二任务分配、路径规划、LLM 约束和态势警报 |
| 决策输出 | `station/` | 生成 `PlanFrame` / `decision_output_frame`，通过 TCP JSON Lines 回发设备一，处理执行回执 |

## 主链路

```text
设备一：雷达清理后的当前战场态势
  -> perception/radar_feed.py / perception/udp_gateway.py 归一化、稳定ID关联
  -> simulation/main.py::InterceptionEnvironment.step(dt)
  -> decision/cooperation.py 任务分配
  -> decision/deconfliction.py 路径规划/避碰
  -> station/contracts.py 生成完整 PlanFrame
  -> station/query.py 裁剪 decision_output_frame / 飞控指令视图
  -> station/exporter.py 按输入帧触发回发设备一
  -> 设备一：操控无人机并在指挥大屏显示
```

## 当前重构原则

- 工程结构和功能模块不大改，优先修正设备边界、触发方式和对外协议语义。
- `PlanFrame` 仍是设备二内部最完整的决策输出帧；`decision_output_frame` 是给设备一直接消费的精简帧。
- 发布触发以设备一输入帧为准：默认 `PLAN_EXPORT["publish_policy"] = "input_frame"`，同一输入帧只回发一次。
- 设备一负责真实飞控执行和大屏显示；设备二不内嵌设备一飞控控制逻辑。
- 配置优先来自 `core/common.py`，不依赖操作系统环境变量。
